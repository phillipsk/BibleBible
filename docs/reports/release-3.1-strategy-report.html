2. Privacy Policy & App Store Compliance Analysis

The addition of operational telemetry and AI summarization requires an audit of our legal posture and app store declarations. The prior policy (dated March 2024) claimed absolute zero data collection. While our new telemetry is 100% first-party, non-PII, and privacy-preserving, the app store guidelines require transparent disclosure of all collected data types.

🍎 Apple App Store (Privacy Nutrition Labels)

Configured under App Store Connect → App Privacy:

  • Data Used to Track You: NO (0%). Zero cross-app or cross-site tracking.
  • Data Linked to You: NO. No user accounts, phone numbers, or emails.
  • Data Collected (Not Linked to You):
    • Usage Data → Product Interaction: App launches, scripture navigation, reels viewed, search events.
    • Diagnostics → Performance Data: AI summary latency, network errors, player buffer failures.
  • App Tracking Transparency (ATT): NOT REQUIRED. Apple only mandates ATT when tracking users across third-party apps or accessing the device IDFA. BibleBible does neither.
🤖 Google Play Store (Data Safety Declaration)

Configured under Google Play Console → Data Safety:

  • Data Collected:
    • App Activity → App Interactions: Feature usage, reels watched, search queries.
    • App Info and Performance → Diagnostics: Crash logs, latency, error telemetry.
  • Data Shared: NO. Never shared with third parties or advertisers.
  • Data Handling Practices:
    • Encrypted in transit: Yes (HTTPS / TLS 1.3).
    • Account creation: Not required.
    • Data deletion: Ephemeral session data automatically ages out; no persistent user profile exists.

3. Authentication, Token Economics & Abuse Prevention

The user expressed valid concerns: "What do you think about concerns about token costs and credit usage right now where there's no real login? Are we exposing ourselves to excessive costs as well?"

Current Architecture & Vulnerability Exposure

Current Protective Safeguards
  • HMAC Bootstrap (/v1/config): Issues short-lived (1-hour) signed JWTs.
  • Rate Limiting: 20 RPM per IP sliding window on Cloud Run.
  • Daily Quota: 500 Gemini requests/day max across the entire cluster.
  • Summary Caching: In-memory LRU cache on Cloud Run avoids re-querying Gemini for identical chapters.
  • Hard Billing Cap: GCP Cloud Billing Budget strictly caps monthly account spend at $100.
Vulnerabilities Without User Authentication
  • Scripting / Reverse Engineering: A malicious actor could extract the client secret from the APK/IPA and script requests directly to /v1/config.
  • IP Rotation & Quota Denial: By using proxies or VPNs, an attacker could bypass the 20 RPM per-IP limit and deplete the 500 daily Gemini requests in minutes, denying service to real users.
  • GCS Video Egress Spikes: Automated download loops could generate unnecessary egress traffic ($0.12/GB), burning budget toward the $100 cap.

Token Cost Realities: Gemini 1.5 Flash vs. Pro

Understanding the exact token pricing dispels fear of runaway costs during normal usage:

Model Input Price (per 1M tokens) Output Price (per 1M tokens) Avg Chapter Cost (~2k in, 250 out) Cost for 500 Daily Requests
Gemini 1.5 Flash (Recommended) $0.075 $0.30 $0.000225 $0.11 / day ($3.37 / month)
Gemini 1.5 Pro $1.25 $5.00 $0.003750 $1.87 / day ($56.25 / month)

*With our server-side caching (which caches summaries across all users for common books like John, Psalms, Romans), repeated hits cost $0.00 in Gemini API tokens.

Recommended Multi-Tier Security Roadmap

Phase 1: Firebase App Check
Zero Friction

Integrate DeviceCheck / App Attest (iOS) and Play Integrity (Android). Validates that API calls originate from genuine, unmodified app binaries on genuine hardware. Blocks 99.9% of headless bots and scripts without forcing users to log in.

Phase 2: Firebase Anonymous Auth
Zero Friction

Issue a silent, cryptographic device UID stored in Keychain/EncryptedSharedPreferences. Cloud Run applies rate limits per UID (e.g. max 15 AI summaries/day per device). If one device misbehaves, only that UID is throttled, leaving other users unaffected.

Phase 3: Optional Social Login
High Value

Provide Sign in with Google and Sign in with Apple for users who want cross-device sync of bookmarks, notes, and reading plans. Signed-in accounts can receive higher AI summary allowances (e.g. 50/day).

CRITICAL INDUSTRY UPDATE: Google Cloud Source Repositories Deprecation
Google officially deprecated new project creation for Google Cloud Source Repositories (CSR) in June 2024. Google Cloud documentation explicitly recommends that all teams use GitHub or GitLab as their source code repository. Attempting to use CSR for a new project is now unsupported.

Comparison of Version Control Options

Platform Agentic AI Tooling (Antigravity, Codex, Copilot) Mobile & KMP CI/CD (macOS / Android) Google Cloud Integration Verdict
GitHub (Current) Industry Benchmark. Native CLI (gh), PR reviews, Copilot, Antigravity git worktree support. First-Class. Native macOS runners for iOS Simulator/XCFramework builds, setup-java, Android SDK caching. Seamless via GCP Workload Identity Federation (keyless OIDC). Direct deployment to Cloud Run and GCS. Strongly Recommended (Keep)
Google Cloud Source Repositories (CSR) Poor. No PR review platform, no agentic tooling hooks. None. Requires external CI orchestration via Cloud Build triggers. Native GCP, but DEPRECATED by Google in 2024. Unviable (Deprecated)
GitLab (Cloud / Self-Hosted) Good, but secondary to GitHub for AI agent tools and community extensions. Requires self-hosted macOS runners for iOS builds. Supports OIDC and GCP integrations. Viable, but unnecessary migration overhead
Gerrit / Piper (Google Internal) High friction; designed for monorepos with dedicated infrastructure teams. Complex setup; no native mobile CI runners. Custom tooling required. Not Suited for Mobile Apps
