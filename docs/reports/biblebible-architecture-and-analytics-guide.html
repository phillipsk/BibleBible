2. Summary of Architectural Decisions (ADRs 0001–0005)

ADR 0001 · Security & Gateway

First-Party Cloud Gateway & Short-Lived Tokens

Eliminated all client-embedded third-party API keys (RapidAPI / Gemini). Clients bootstrap from GET /v1/config and receive short-lived HMAC-SHA256 bearer tokens (sessionToken). All 6 public-domain Bible translations (KJV, BSB, WEB, BBE, RV1909, SVD) are served first-party with immutable edge caching; Gemini calls are rate-limited and cached server-side.

ADR 0002 · Cross-Platform Media

KMP Shared UI + Native Video Players

Kept 100% of navigation, controls, scrubber state, and pager logic in shared Compose Multiplatform (commonMain) while bridging native hardware video playback via expect/actual: TextureView + MediaPlayer on Android, AVPlayer + AVPlayerLayer on iOS, and storyboard playback on Desktop.

ADR 0003 · Cost Guardrails

Biblical Words Pipeline & <$100/mo Spend Cap

Curated short-form scripture videos hosted on Google Cloud with HTTP 206 range streaming, Cloud Run concurrency/instance caps (--max-instances=2, scale-to-zero), and GCP Cloud Billing budget alerts enforcing a strict sub-$100/month operating ceiling.

ADR 0004 · Telemetry

First-Party Privacy-Preserving Analytics

Built a zero-SDK, first-party telemetry pipeline instead of Firebase Analytics/Mixpanel. Ephemeral per-session IDs only (no IDFA, GAID, IP storage, or PII), batched offline-safe delivery every 15 seconds, and a live HTML dashboard hosted directly on Cloud Run.

ADR 0005 · Accounts & Sync

Optional Firebase Auth via REST + Firestore Sync

Reading stays completely free without login. Opt-in accounts support Apple, Google, and Passwordless Email via Firebase Auth REST APIs (avoiding Desktop SDK blockers), exchanged for first-party tier="user" session tokens with full App Store / Play Store compliant instant account deletion (DELETE /v1/me).

Release 3.1 · Dynamic Control

Backend Feature Flags & Edge-to-Edge Polish

Added server-driven booleans in GET /v1/config (features.biblicalShortsEnabled, features.verseOfTheDayEnabled) so Home modules can be toggled live on Cloud Run without shipping a binary update.

3. How First-Party Analytics Work & How to View Them

Client Collection (KMP AnalyticsTracker)

  • Instrumented across Home, Bible Reader, Chapter Tabs, Translations, Search/Sort, AI Summaries, Biblical Words, and Auth lifecycle.
  • Queues events in memory and flushes batches to POST /v1/analytics/events every 15s (or immediately on app pause/background) with exponential backoff.
  • Privacy-first: attaches only an ephemeral session ID + platform (android, ios, desktop). Never transmits emails, UIDs, or device advertising IDs.

Live Dashboard & Historical Logs

  • Live Operational Dashboard: /analytics — auto-refreshing KPI cards, platform split, top books, top translations, top clips, and recent event stream.
  • Raw JSON Feed: /v1/analytics/summary.
  • Historical Queries (Cloud Logging): Open Cloud Logs Explorer and run:
    jsonPayload.component="biblebible-analytics"

4. Toggling Backend Feature Flags Live (Zero App Release)

Flip Biblical Words or Verse of the Day on/off instantly via Cloud Run environment variables:

gcloud run services update biblebible-api \
  --project gen-lang-client-0150678391 \
  --region us-central1 \
  --update-env-vars FEATURE_BIBLICAL_SHORTS=true,FEATURE_VERSE_OF_THE_DAY=true

To deploy new backend code (including the latest auth, sync, and feature flag endpoints):

./backend/scripts/deploy-gcp.sh gen-lang-client-0150678391 us-central1

5. Should backend/ Be Version Controlled?

Recommendation: Yes — in a Separate Private Repository

Keep backend/ ignored in the public frontend repo (phillipsk/BibleBible) so server rate-limit tuning, deployment scripts, and internal gateway logic stay private — while initializing a dedicated private GitHub repository (e.g. phillipsk/BibleBible-backend) inside backend/ so you never risk losing backend code if your laptop dies and can track rollback history cleanly.

  • Frontend repo stays clean, open-source-safe, and verified by tools/verify_no_client_secrets.py.
  • Private backend repo gives full version history, PR diffs, and optional Cloud Build auto-deploy triggers on push to main.
